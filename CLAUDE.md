# AgentDesk — context for Claude Code

Evan's automated options trading desk on Robinhood Agentic Trading (MCP), built in a claude.ai session on 2026-09-27. **Read HANDOFF.md (v3) first.** It has the full rules for all five strategy books, the backtest tables, the multi-book build spec (section 9), the phased plan with acceptance criteria (section 10), sizing (11) and safety rules (12). This file is the short version.

## What exists
- `agentdesk/` Python engine (deterministic rules) + FastAPI/websocket dashboard with a pixel-art office (`web/`). Modes: `sim` (synthetic day, calm/event moods), `paper` (default: real data, simulated fills), `shadow` (every order sent to `review_option_order`, fills simulated), `live` (needs `live_enabled: true` + `robinhood.account_number`).
- Dashboard panes resize with draggable dividers (`web/layout.js`: chart vs side column, chart vs trades, side cards vs office; arrow keys work, double-click resets, sizes kept per browser). The page scrolls below 600 px tall and stacks below 900 px wide.
- Shutdown (Ctrl-C/SIGTERM, `lifecycle.py`) sells every open position first via `engine.flatten("shutdown")`, in every mode (Evan, 2026-09-28: "dont leave them open"); leftovers after 8 s are logged; then it saves the review snapshot, cancels the pollers and only then closes the Robinhood and data sessions; a second Ctrl-C exits at once. If the engine task crashes, the same shutdown runs and `run` exits with status 1, so the review page takes the port.
- After-hours dashboard (Evan, 2026-09-30; spec `docs/superpowers/specs/2026-09-30-after-hours-review-design.md`): `python -m agentdesk review` (launchd `com.agentdesk.review`, KeepAlive, installed by `tools/install_paper.sh`, which tests each release before switching to it and verifies the paper, review and quant jobs loaded) serves the last saved session read-only on the engine's port: GET only, no websocket, no broker/data/Claude calls. Paper/shadow/live runs save `review.sessions_dir/YYYY-MM-DD.snapshot.json` (every 60 s and after the shutdown flatten) and `.events.jsonl` (feed events via a `Bus` tap; position mark updates skipped) from `__main__.run_session`; `engine.py` is untouched. `run` and `paper_session.sh` claim the port with a pid file in `review.claims_dir` holding the process start time, so a reused pid can't keep a claim; the review server listens only while no live claim exists and the engine waits up to 15 s for the port. An open live tab reloads into the review page when the engine stops; both apps send `Cache-Control: no-cache` (`no-store` for /config.js). If the newest snapshot is unreadable, the review page shows the newest readable day.
- Mac jobs (`tools/install_paper.sh`, `tools/install_recorder.sh`, shared steps in `tools/deploy_lib.sh`): each install builds `~/.agentdesk/<app>/releases/<stamp>` from requirements.lock, runs the tests there and switches `current` only on a pass ("Not deployed; the live release is unchanged" otherwise). Both refuse a dirty checkout unless `--dirty`; the paper installer refuses while an engine runs unless `--force`. `com.agentdesk.paper` fires at 08:10 weekdays in the Mac's system time zone and at login (RunAtLoad): it exits on weekends, `calendar.holidays`, before 06:00 CT and after 15:00 CT, waits for 08:10 CT when started earlier, and logs a WARN when the system zone isn't Central. `com.agentdesk.quant` (Fridays 16:00, `tools/quant_week.sh`) runs book A's SIP replay, the weekly Quant report (with the Post-mortem files) and, on a month's first Friday, `tools/prune.sh`.
- CLI: `python -m agentdesk run | review | record-demo | rh-inspect | backtest | l2-report | iv-snapshot`.
- Book A (Evan's MACD 0DTE calls) is fully built in `engine.py`. Books B, C, D are built in `agentdesk/books/` (paper only; every fill simulated by `PaperBroker.submit_combo` at mid −1¢/leg, never worse than natural; shadow only adds a read-only `review_option_order`). `BookHost` runs them from one-line engine hooks; book A's path is unchanged. Book E runs in `books/e_host.py` (`EHost`, joined through `HostGroup` with `BookHost`, F1's `FHost` and F2's `F2Host`); it holds for days, so its positions are saved in `e_positions`, restored at startup and not sold at shutdown (Evan approved 2026-09-29). F2 does the same with `f2_positions`. A book's id is its config key's prefix before the first underscore (`F1_stocks_in_play` -> F1); journal rows written as book `F` read as F1.
- Multi-book account (`books.account`): $10,000 paper balance, $2,500 open-risk cap (book A's open debit counts; Evan raised it from $1,500 on 2026-09-29), $300 max loss per B/C/D position, C budget $400 (the lower wins), $0.04 fee per leg (book A pays the same per contract per side, `sizing.fee_per_contract`). Book A's −$400 day halt and profit lock halt and flatten book A only (`halt_scope: "A"`); only an account-wide halt (kill switch, safety halt) stops every book (Evan, 2026-10-01). A restart restores each sticky halt with its own scope (A's own halts stay A-only); startup checks re-run and are never restored. A stale-quote watchdog trip halts and flattens book A and the 0DTE books B/C/D/G; E and F2 keep running, and so does F1 unless the stale position is its own (Evan, D3, 2026-10-07). After a restart A stays halted and B/C/D/G resume. A restart rebuilds each book's day (trades, wins, losses, P&L, F1's −$75 and F2's −$300 day limits, F1's one entry per name) from the journal's `trades`. A book that errors `max_consecutive_errors` times in a row halts and flattens itself only; each kind of call (clock check, position check, bar hook) keeps its own streak, so a clean call of one kind never hides another kind failing. For E and F2 a quote read that fails while no exit is due is logged once per outage and not counted; a flatten without fresh quotes closes at the last mark, flagged "quotes unavailable". `paper_only: true` is enforced; live mode needs exactly one promoted book and only A has a live path (`check_live_promotion`).

## The crew (`crew.py`, `proposals.py`)
- Desks: Macro, Rates, Fed, Vol, Quant, Risk, Tape, plus restrict-only Ops (pre-flight), Earnings (book E screen) and Post-mortem (rule audit) in `desks.py`. At huddles they brief, then talk to each other in a roundtable (lines carry from/to; only desks in that huddle can revise), then vote size 0.5–1.25×.
- Crew review changes (Evan approved 2026-09-29, spec `docs/superpowers/specs/2026-09-29-crew-review-changes.md`): Rates and Fed are `INFO_ONLY`, derived from Macro's `rates`/`fed` sub-briefs with no web call and a fixed 1.0 vote. Vol reads VIX from Robinhood and the expected move from the recorded straddle; its one web call is premarket (VIX1D, vote). Every Vol read re-applies the VIX > 28 cut to 75% from the current VIX, so the cut lifts when VIX falls back. A weekly econ calendar (`crew.calendar_path`) adds blackouts next to Macro's. Votes reach only the books in `crew.vote_books`; `RiskManager.book_mult(letter)` holds one multiplier per book. `journal.crew_log` and `trades.crew` record the crew's effect; the weekly Quant report scores it. `crew.model` is claude-sonnet-5-5; Haiku 4.5 does Quant notes and the roundtable.
- Any vote below 1 cuts size for the books that vote reaches (lowest wins). A size-up (max 1.25×, book A SWING only) needs every check in `Crew.size_up` to pass; the checklist shows on each entry.
- Proposals (rules Evan approved):
  - Next-trade and today tweaks auto-apply, but only for the `TWEAKS` whitelist within hard bounds: stop 10–25%, trail, first target, RSI cap, earlier cutoff, fewer trades, skip a setup, strike distance.
  - The crew can never change size or loss limits, including anything under `books.*`.
  - Standing changes and new strategies wait for Evan's Approve button. Approved strategies are built and backtested first; nothing new trades on its own.
  - Suggestions clear once their reason has passed (Evan, 2026-10-01): today's tweaks at the end of the day; a standing change at the desk's `until`, else after the event it cites (FOMC, CPI, payrolls..., from blackouts, the weekly calendar or config), else after `crew.proposal_ttl_days.standing` (5); new strategies only at a desk's `until`. Expired items keep status `expired` in proposals.json, leave the dashboard and can't be approved. Re-pitching the same standing change refreshes its card. proposals.json is written atomically; an unreadable one is kept as `.corrupt-<ts>`. After a mid-day restart today's applied tweaks are re-applied (or marked expired with the reason) and next-trade tweaks are marked expired.
  - One blackout per event time (2026-10-02): `RiskManager.add_blackout` ignores an event whose window matches an existing blackout (a desk rewording the same 07:30 print). An event whose window ended before the desk heard of it blocks nothing and isn't shown, but goes to `passed_events` so book B still skips that day. A brief adds at most 4 events a day, and only future times block entries. Events from a desk's brief never flatten; only the weekly calendar and `crew.events` carry a flatten time (Evan, D4, 2026-10-07). `_finish` strips web-search `<cite>` tags from headlines, notes, event names and pitches.
- Dashboard risk panel (Evan, 2026-10-02): all books combined (realized, closed, W/L), one loss-limit meter per book that has one (A's $400 from risk state, F1/F2 from `daily_loss` in each book's snapshot), only blackouts that haven't ended. Pure helpers live in `agentdesk/web/panel.js`, tested under node by `tests/test_web_panel.py`. Chart markers are for SPY trades only. A tab whose bus queue overflowed gets a fresh snapshot instead of a gap. Book A's position payload carries its exit plan (`plan`), and a day or standing crew tweak sends a `config` event, so the card shows the plan the engine uses. `web/book_f.js` reads app.js's websocket; it has none of its own. The header's REC pill shows whether the standalone recorder is writing (`Engine.recorder_status`, from its heartbeat file; a red REC DOWN in market hours when it isn't, plus a feed warning); it is hidden in sim, the demo and the review page.
- Offline (no `ANTHROPIC_API_KEY`) the crew runs templated briefs and roundtables. Online, Macro (08:25, 11:30), Vol (08:25) and the weekly calendar use web search: 3-4 calls a day holding up to about 12 searches, plus F1's news tag. Outside the simulator huddles run in a background task; a halt calls one huddle per (day, reason).
- Every Claude call (desk briefs, roundtable, book F news tag) puts an explicit `cache_control` breakpoint on its stable system block via `crew.cached_system`; time, price, briefs and stats stay in the user message after it. The breakpoints are harmless but rarely read (no two calls share a prefix inside the 5-minute TTL, and Haiku's 4,096-token minimum is never met), so expect `cache_read` near 0. `Crew.cache_usage` (also in the dashboard state) tallies calls, input/output tokens, cache reads and writes, web searches and estimated cost, in total and per desk.

## Data stack (paper)
- Robinhood MCP: option quotes/greeks, Level 2 (`get_equity_price_book`, Nasdaq TotalView), SPY bars, earnings calendar, order review.
- Free Alpaca IEX feed for SPY prints. IEX carries only about 3.7% of SPY prints (measured 2026-09-28), so on `provider: alpaca` + `feed: iex` the engine uses `tick_bar_size_iex: 5` prints as the "144t" approximation (it logs a warning). The socket checks the subscribe reply, treats a `T:error` message as a drop (reconnect with backoff) and warns once when prints stall for 60 s during RTH. Book A results on IEX are not evidence; judge A by the weekly SIP replay (HANDOFF section 3; `research/iex_vs_sip.py` prices on the trading-day clock, `--clock calendar` matches runs before 2026-10-07). Upgrade to Algo Trader Plus (SIP + OPRA, $99/mo) before live if A looks effective or data turns out to be the blocker.
- The recorder saves real 0DTE quotes, ATM−10..ATM+10 calls and puts, every 10s into `journal.option_quotes`. That is the data for real-quote analyses of A, B, C and D. Rows older than 90 days move each month to `~/.agentdesk/archive/quotes-YYYY.db` (`tools/prune.sh`, `tools/prune_journal.py`); the weekly Quant report reads the archives too, so a script reading the journal directly should attach them.
- Book E's IV pass runs inside `record-quotes` (read-only, metered as tag `iv`): it lists strikes from 13:30 CT at ≤ 0.5 calls/s and quotes the ATM call and put in the front, pre-report, post-report and ~30-day expiries from 14:50 CT at ≤ 1 call/s, into `journal.iv_history`. `iv-snapshot` runs it once by hand.
- 1m/5m/15m bars are final once closed: a print that arrives after its bar closed (IEX prints can be late) is dropped from the time bars, never opens a second bar for the same minute, and is counted in the log. 144t bars take RTH prints only. A mid-day restart warms up from IEX history up to the current minute (SIP keeps its 16-minute lag); the builders continue today's periods, a partial period never reaches MACD/RSI, and the warm-up log gives the gap.
- The journal runs in WAL mode with a 30 s busy timeout (the -wal/-shm files next to it are normal) and indexes on option_quotes(expiry, ts), option_quotes(ts) and rh_calls(tag, ts). A failed trade write is retried once and is never lost from the log.
- Level 2 (`l2.py`) runs in observe mode: it logs book state per entry and never blocks. Use `l2-report` after a few weeks.
- Robinhood throttles near 240 calls/min per account, shared with the recorder. The engine keeps to `robinhood.call_budget` (120/min, 3/s; `RobinhoodMCP` paces every call and pauses 2-8 s after a RATE_LIMITED, which never counts toward a book halt or the engine's safety halt (the stale-quote watchdog skips seconds in which the budget held every call); a call with no reply in `call_timeout_sec` (20 s) fails, and a dropped session, or 2 timeouts in a row, reconnects), polls Level 2 every 3 s, and quotes every open B/C/D/G leg in one call per second. The recorder keeps its own budget (`recorder.call_budget`, 100/min, 5/s; `--probe` is uncapped). When a token can't refresh, the sign-in URL goes to the log and the dashboard, and connect waits up to 330 s for it.

## Robinhood facts verified 2026-09-27
- Agentic account: limited_margin, **option_level_3**, a small cash balance. Show only the last 4 digits in anything user-facing, and never commit the number, its last 4 digits or the balance to this public repo.
- `review_option_order` accepted a 2-leg credit spread. Multi-leg orders need `direction`. Arg shapes are in `brokers/robinhood.py` (`order_args`, `fit_args`), and schemas have additionalProperties:false.
- SPY 0DTE `sellout_datetime` = 14:45 CT. Same-day opens are allowed until 3:30 PM ET; at-risk closeout starts 3:30 PM ET (3:45 for SPY). The engine flattens at 14:40 CT and 5 min before each contract's sellout. Short legs are never held into 3:30 PM ET.
- `get_option_historicals` returns only gap-filled bars for expired 0DTE contracts, so it can't be used for option backtests.
- The current cash balance is too small for the default sizing. See the HANDOFF section 11 table, and ask Evan before changing any size or risk value.

## Research (research/, reproducible)
- 11 published intraday strategies: none significant out-of-sample. Evan's MACD proxy: t 0.23 / 1.69 / 0.39.
- The variance risk premium (short 0DTE premium) is the one robust effect, modeled from VIX. B and D both rely on it.
- `strategies_bcd.py` -> `strategies_bcd_results.json` covers B, C (both directions), D and cost/IV sensitivity. Options are modeled with Black-Scholes from VIX (M_RTH 0.80), re-based to SPY 765.
- Book A variants (`book_a_variants_prereg.md`, results `book_a_variants.md`, 2026-10-02): no RSI cap, puts, 15m-only filter and 5m cross-back exits all fail on 2005-2020 1-minute data; the baseline loses ~$7-14/day, extra trades lose at the same rate, and the -20% premium stop fires on one-minute noise (1,409 stops inside a minute). These 2005-2020 tables are on the cheap-option model: `pricing.py` used a calendar-time clock until 2026-10-07, pricing 0DTE calls at about half of real (`ModelQuotes` now defaults to the trading-day clock; `book_a_variants.py` stays pinned to calendar). The real-quote holdout is unaffected. `book_a_holdout.py` (Mac) runs the baseline, v1, SWING-only and round 2's stop/strike variants (`book_a_round2_prereg.md`) on real ThetaData quotes and SIP ticks: nothing passes (baseline −$24/day on 2020-26 real quotes, t −6.4; the −35% stop is $10/day better but still −$14/day; SWING-only least bad on 60 tick days, −$12/day); 1-minute quote rows are re-centred on the current SPY price by delta/gamma, because raw rows lag the signal and fake a large profit (first run, PF 5.9, discarded).
- Book H candidates (`book_h_candidates_prereg.md`, 2026-10-06, PR #47): SPY overnight hold, overnight after a down day and the RSI(2) dip fail on 2005-2020 data (out-of-sample t −0.51 / +0.06 / −0.33). H4, an overnight 1DTE iron fly (sell ATM at 15:50 ET, $5 wings, buy back 09:45 ET), fails on 2016-2026 ThetaData quotes (`h4_overnight_fly.md`): +$1-2/lot at mid, −$5.08/lot at mid −1¢ out-of-sample (t −3.23), −$10.71 at taker; every year negative at mid −1¢. The overnight premium is real but smaller than four legs' costs. Next-expiry quotes are in `data/thetadata/spy_next` on the Mac (`fetch_thetadata_spy_next.py`).
- V1, short VIX futures carry (`vix_carry_prereg.md`, 2026-10-06): SVXY at −0.5x while VIX/VIX3M < 1 (one-session lag), on an SPVXSP index rebuilt from CBOE VX settlements (correlation 0.979 with real SVXY). **FAIL**: in-sample 2009-09..2014 +11.3 bp/day (t +2.22), out-of-sample 2015-2026 +4.35 bp/day, t +1.09 (bar 2.33), Sharpe 0.32, max drawdown −65%, worst day −48% (2018-02-05). Positive after costs but too noisy and fat-tailed to pass (`vix_carry.md`). Mac-only data (`fetch_cboe_vx.py`).
- F1/F2 research track (scripts and pre-registrations committed, no results yet; runs on Evan's Mac): `strategy_f_intraday.py --universe broad` (F1 v2), `f2c_drift.py` (does the stock drift after F2-C's entry; cached shares data), `f2_real_quotes.py` + `fetch_thetadata_equity.py` (F2 on real single-name quotes, needs ThetaData equity options). `strategies_equity_prereg.md` is a draft list of other candidates (earnings IV crush, post-earnings drift, reversal and gap-fade holdouts on names the daily study never saw); nothing in it is built until Evan approves it.

## Rules for working on this repo
- Never call `place_option_order`, `cancel_option_order` or `exercise_option` yourself. Orders go only through the engine in `--mode live` with `live_enabled: true`. Keep MCP permission prompts ON for those tools.
- Paper stays the default. Don't change strategy rules (A as Evan trades it, B as specified) without asking. A filter added after seeing results is a new variant to test separately.
- Run `python -m pytest -q tests research/tests` after changes (925 + 192 pass on 2026-10-07, about 2-3 min; `-m 'not slow'` skips the synthetic-day replays). GitHub Actions runs both on Python 3.12 from `requirements.lock`; after changing requirements.txt re-run `uv pip compile requirements.txt -o requirements.lock --python-version 3.12`. Rebuild the demo with `tools/build_demo.py` if the UI changes.
